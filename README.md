# real 출퇴근 위젯 자동 점검

네이버웍스 real 환경(home.worksmobile.com)에서 근무 유형별 계정 6개가 출근·퇴근을 정상으로 할 수 있는지 Playwright로 확인합니다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `tests/real/real_att.spec.js` | 18시 이후 근무 계정 6개(work1~6) 출근 후 퇴근. 선택근무는 근무 일정이 없으면 신청·상신 후 재진입해 출근. 보통 배포때 사용|
| `tests/real/real_att_reset.spec.js` | 위 계정 6개의 출퇴근 기록만 초기화. |
| `tests/real/real_att_day.spec.js` | 낮 근무 계정 6개(work101~106) 출근 후 퇴근. 09시 부터 ~18시 테스트 용도|
| `tests/real/real_att_day_reset.spec.js` | 위 계정 6개의 출퇴근 기록만 초기화. |

## 사전 설정: 출퇴근 허용 IP 등록

테스트를 돌리는 PC의 공인 IP가 각 계정의 근무 방식에 허용 IP로 등록되어 있어야 합니다. 등록되지 않으면 "현재 IP 주소에서는 출퇴근을 체크할 수 없습니다." 토스트와 함께 해당 계정은 건너뛰어집니다.

1. 관리자 계정으로 관리자 서비스에 들어가 **근태 > 근무 > 근무 방식 관리**를 엽니다.
2. 테스트 계정이 쓰는 근무 방식(고정·선택·시차·교대·탄력·개인별일정)마다 **수정**을 누릅니다.
3. 아래 사진처럼 출퇴근 체크 IP 설정에서 **본인 PC의 IP를 직접 입력**하고 저장합니다.
4. 네트워크(사무실, 재택, VPN)가 바뀌면 공인 IP도 바뀌므로 다시 등록해야 합니다.

## 준비

```bash
npm install
npx playwright install chromium
cp .env.example .env   # 계정 아이디/비밀번호 값을 채웁니다
```

- 테스트 PC의 공인 IP가 계정의 출퇴근 허용 IP에 포함되어야 합니다. 아니면 "현재 IP 주소에서는 출퇴근을 체크할 수 없습니다." 토스트로 건너뜁니다.
- `real_att.spec.js`는 19:00 이후에 실행하세요. 시차근무 계정은 근무 시작(19:00) 전에는 출근이 거부됩니다.

## 실행

```bash
npm run test:att            # 18시 이후 배포 시 계정 출퇴근
npm run test:att:headed     # 브라우저 창을 보면서
npm run test:att:reset      # 야간 계정 초기화

npm run test:day            # 낮 계정 출퇴근
npm run test:day:reset      # 낮 계정 초기화
```

## 진행 순서

1. 결과 폴더(`real_att_results` 또는 `real_att_day_results`)를 비웁니다.
2. 계정 6개를 순서대로 로그인해 출근합니다. 이미 ON이거나 출근 버튼이 없으면 상세 팝업에서 초기화한 뒤 출근합니다.
3. 출근한 계정을 다시 순서대로 로그인해 퇴근합니다.
4. 퇴근이 확인되면 홈 화면 전체를 `라벨 출퇴근확인.png`로 저장합니다. 화면 상단에 라벨/계정/시각 띠가 들어갑니다.
5. 퇴근 실패나 예외가 하나라도 있으면 테스트가 실패로 끝납니다. 출근 단계에서 건너뛴 계정은 실패로 집계되지 않으므로 결과 폴더에 확인 파일이 6장 있는지 함께 보세요.

## 부정 토스트(빨간 오류 토스트) 처리

| 토스트 | 대응 | 스크린샷 |
| --- | --- | --- |
| 출근과 퇴근에 같은 시간을 입력할 수 없습니다. | 20초 후 재시도, 최대 3회 | 1·2회차 생략, 3회차에 저장 |
| 근로 시간을 선택하세요. | 근로 시간 라디오 선택 후 1회 재시도 | 재시도 실패 시 저장 |
| 현재 IP 주소에서는 출퇴근을 체크할 수 없습니다. | 해당 계정 건너뜀(퇴근도 제외) | 즉시 저장 |
| 그 밖의 빨간 토스트 | 로그에 남기고 건너뜀. 퇴근 단계면 실패로 기록 | 즉시 저장 |

스크린샷 이름은 `라벨 부정 토스트 확인.png`이며 같은 계정에서 여러 장이면 `확인1`, `확인2`처럼 번호가 붙습니다. 성공(파란) 토스트는 찍지 않습니다.

## 알아둘 점

- 실제 데이터가 바뀝니다. 출퇴근 초기화·출근·퇴근이 실제로 수행되고 선택근무는 근무 일정 신청 문서가 상신됩니다. 테스트 계정에서만 사용하세요.
- 탄력근무는 출근만 기록하는 유형이라 퇴근 버튼이 없어도 정상 출근으로 처리합니다.
- 계정 아이디와 비밀번호는 `.env`에만 두고 저장소에는 올리지 않습니다. 변수 이름은 `.env.example`을 참고하세요.
